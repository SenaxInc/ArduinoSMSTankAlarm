# TankAlarm v2.2.13 — Alarm Reminder Snooze / Unsnooze

Server-only release. Client and Viewer are version bumps only.

## New: Snooze reminders for an active alarm

When a sensor alarm is confirmed but the field fix is days away, the recurring reminder
texts/emails (every `smsReminderHours`, default 6 h) can now be paused per sensor without
touching alerting for the rest of the fleet.

- **Dashboard**: alarming sensor cards gain a **Snooze Reminders** / **Unsnooze** button and a
  "reminders snoozed" note in the alarm banner.
- **SMS reply**: recipients can text **SNOOZE** or **UNSNOOZE** back to the alert number
  (requires the Twilio inbound Function from `/sms-setup`). Commands are honored only from
  numbers in the alarm's own recipient list — unknown numbers are logged and ignored.
- **Everyone stays informed**: snoozing/unsnoozing broadcasts a one-time notice to all of the
  alarm's subscribed SMS/email recipients, so reminder silence can never be mistaken for "fixed".
- **Auto-reset**: when the sensor returns to normal (any alarm-clear path), the snooze clears
  itself — the next excursion alerts and reminds normally. The recovery notification still sends.
- **Unsnooze timing**: after unsnooze, the next reminder lands one full reminder interval later.
- Snooze state persists across server reboots (saved immediately in the sensor registry).

## What snooze does NOT affect

Initial alarm notifications for new alarms, return-to-normal notifications, daily reports,
stale-client alerts, system alarms (solar/battery/power), and OTA alerts all behave as before.

## API

- `POST /api/alarm/snooze` `{client, sensor, action: "snooze"|"unsnooze"}` (session-auth)
- `GET /api/clients` per-sensor objects now include `sz` (snooze epoch) when snoozed.

## Docs

- `/sms-setup` Step 4 now documents the SNOOZE/UNSNOOZE keywords.
