# TankAlarm v2.2.14 — Hotfix: sensor lookups failed after reboot

Server-only hotfix. Client and Viewer are version bumps only.

## Fixed

- **"Unknown sensor" from the Snooze button (and any hash-keyed API lookup) after a server
  reboot.** `loadSensorRegistry()` inserted each record into the sensor hash table *before*
  incrementing the record count; the insert helper rejects `index >= count`, so every insert
  at boot silently no-op'd and the hash table stayed empty until the next telemetry note for
  a sensor upserted it (self-heal path). Sensors that hadn't reported since boot were visible
  on the dashboard (array iteration) but invisible to `findSensorByHash()` — which broke
  `POST /api/alarm/snooze` for the exact alarm it was built for. Load order is now
  increment-then-insert, matching the upsert path.

Latent since the hash table was introduced; v2.2.13's snooze button was the first
user-facing path to hit it on a server whose alarming client reports infrequently.
